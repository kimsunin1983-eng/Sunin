# v7.6 통역·검산 수정

## 변경

- 1.2초 타이머는 출력 방향만 결정한다. 정상 출력 폐기와 검산은 서버 turnComplete에서만 수행한다. 1.5초 수신 공백으로 문장을 나누지 않는다.
- 마이크 음성은 앞 여유 300ms, 종료 무음 800ms로 모은다. 번역 출력이 시작된 뒤에도 같은 발화의 뒷부분을 수집한다.
- 로컬 발화 경계와 서버 응답의 대응은 보수적으로 판단한다. 미완성·복수 발화·겹침·30초 초과·오래된 음성은 자동 교정과 재번역에 사용하지 않는다. 원래 실시간 번역은 유지한다.
- 대문자·두 단어라는 이유만으로 미번역 결과를 허용하지 않는다. OK, USB, Wi-Fi 등 명시된 공통 표기는 바로 통과한다. 그 밖에는 Gemini와 Google 번역이 모두 원문 그대로 돌려주고, 같은 글자를 쓰는 언어쌍에서는 반대 방향 번역도 실패했을 때에만 한두 단어(이름, 두 언어에서 같은 말)를 그대로 통과시킨다. 글자가 다른 언어쌍에서는 한 단어일 때만 해당한다.
- 검산은 양쪽 전체 번역을 JSON으로 전달한다. 어느 한쪽이 16,000자를 넘으면 비교를 건너뛰며 일부분끼리 비교하지 않는다.
- 검산은 세션마다 별도 실행기(실행 1 + 대기 2)를 사용한다. 이전 세션의 늦은 완료가 새 세션의 대기 수를 바꾸지 않는다.
- 중지 시 스피커 재생 예상 시간을 초기화한다. 원문만 교정된 경우에도 이후 대화 문맥에 반영한다.

## 자동 검증

`gradle testDebugUnitTest assembleDebug --stacktrace`

회귀 테스트: 지연된 Music 접두어, 불완전 괄호, 일반 문장/명령의 미번역 거부, 공통 표기 허용, 400자 뒤 의미 보존, 비교 길이 상한, 발화 뒷부분 수집, 완성/미완성 음성, 복수/겹친 발화, 과긴 발화, 취소, 무음, 오래된 음성, 이전 검산이 늦게 끝나는 재시작.

## 실제 휴대폰에서 확인할 사항

- 한↔영: 네/아니요/Yes/No가 상대쪽으로 출력되는지.
- Wi-Fi/모바일망 전환 시 문장이 중간에 폐기되지 않는지.
- 5초·15초·30초 발화, 숨 고르기, 두 사람이 겹쳐 말하기. 검산 생략은 정확도 판정이 아니며 원문을 보존하기 위한 제한이다.
- 스피커/블루투스 이어폰에서 반향, 실제 음량, 출력 방향 확인.
- 검산 중 중지 후 즉시 재시작하고 이전 문장이 최신 화면을 덮지 않는지 확인.

실제 음성 정확도, 로컬 음성 감지 임계값, 기기별 오디오 경로는 자동 테스트만으로 검증되지 않는다.
